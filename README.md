# Remnawave Node Installer

Однокомандная установка Remnawave Node на чистый Ubuntu/Debian-сервер с Docker и ротацией логов. По умолчанию **без zapret.dat**. Установщик предназначен только для чистого сервера, а не для обновления существующих нод.

## Установка по шагам

### 1. Подготовь ноду в панели Remnawave

1. Создай новую ноду в панели Remnawave.
2. Укажи IP-адрес или домен нового сервера и нужный порт.
3. Сохрани ноду.
4. Открой выданный панелью уникальный `docker-compose.yml` и скопируй его целиком.

У каждой ноды свой `SECRET_KEY`, поэтому нельзя использовать compose от другой ноды.

### 2. Подключись к новому серверу

Подключись к чистому Ubuntu/Debian-серверу по SSH под `root` или пользователем с `sudo`.

Установщик предназначен именно для сервера ноды. Не запускай его на сервере, где установлена панель Remnawave.

### 3. Запусти установщик

```bash
curl -fsSL https://raw.githubusercontent.com/igorlion/remnanode-installer/main/install-remnanode.sh | sudo bash
```

Дождись приглашения вставить compose. Затем:

1. Скопируй уникальный `docker-compose.yml` ноды из панели Remnawave.
2. Вставь его в терминал целиком.
3. Нажми **Enter**, затем **Ctrl+D** (на пустой строке).

Дописывать `END` или `__END__` больше не нужно. `Ctrl+D` завершает только ввод
compose; установщик продолжает работу. Если последняя строка не завершена Enter,
первое Ctrl+D может только передать её терминалу; поэтому сначала нажми Enter.
Не используй Ctrl+C: это прерывание установки.

Если compose уже сохранён на сервере, ручная вставка вообще не нужна:

```bash
curl -fsSL https://raw.githubusercontent.com/igorlion/remnanode-installer/main/install-remnanode.sh -o /tmp/install-remnanode.sh
sudo bash /tmp/install-remnanode.sh --compose-file /root/node-compose.yml
```

Файл содержит секрет ноды: держи его в закрытом каталоге с правами `600`.
Установщик читает файл, но не удаляет и не изменяет его. Параметр можно сочетать
с `--with-zapret`, если это отдельно требуется.

### 4. Дождись завершения

Установщик проверит compose, скачает образ и запустит контейнер. В конце должно появиться:

```text
Контейнер запущен. Это ещё не подтверждает работу Xray и клиентского VPN.
```

После этого вернись в панель Remnawave и проверь, что нода перешла в состояние подключения. Обычно это занимает несколько секунд.

### 5. Если нода не подключилась

Посмотри состояние контейнера и последние логи:

```bash
cd /opt/remnanode
docker compose ps
docker compose logs --tail=100 -t
```

Также проверь, что `NODE_PORT` разрешён в firewall сервера и доступен с IP панели.

### 6. Проверь Xray и клиентское подключение

Запуск контейнера не доказывает работу VPN. Проверь связь с панелью, выбранные inbounds,
прослушиваемые порты, память Xray и фактический выходной IP через клиент.

Для лёгкого серверного роутинга на RU база `zapret.dat` не нужна:

1. `geosite:category-ru` и `regexp:\\.(ru|su|xn--p1ai)$` в JSON → `DIRECT_RU`.
2. `geoip:ru` → `DIRECT_RU`.
3. Остальное из клиентского inbound → `VLESS_OUT_TR`.

Правила и `freedom` outbound добавляются отдельно в профиль панели. Установщик не меняет
профили Xray, ключи и маршрутизацию. Категории должны присутствовать в используемых geosite/geoip.
Для трёхзвенной цепочки проверь выход остального трафика через TR и US.

## Что делает установщик

- До установки пакетов проверяет существующие каталоги ноды, контейнер и старые zapret-компоненты.
- При обнаружении существующей/частичной установки отказывается продолжать; ничего не мигрирует.
- Принимает compose из панели через терминал и хранит временную копию с закрытыми правами.
- Устанавливает Docker, Compose plugin и logrotate; это изменения системы на новом сервере.
- Проверяет Compose, сохраняет конфигурацию с правами `600`, запускает сервис `remnanode`.
- Подключает каталог логов; сами access/error logs нужно включать отдельно в профиле Xray.
- Не меняет firewall, SSH, DNS и профили Xray.
- По умолчанию не скачивает zapret, не создаёт загрузчик и таймер.

Не запускай скрипт повторно для исправления неудачной установки: при ошибке возможны уже
установленные пакеты и сохранённые файлы. Сначала проверь состояние. Автоматического отката
установки Docker нет. Секреты не должны попадать в репозиторий или публичные журналы.

## Необязательная установка zapret.dat

**На RU с 870 MiB RAM база около 42 MB приводила к OOM. Для этой ноды используй режим без zapret.**
Размер файла не равен памяти после загрузки. Опция ниже требует минимум 2 GiB физической RAM
(без учёта swap); это предохранитель, а не гарантия достаточной памяти.

Только для нового сервера с отдельно проверенным запасом ресурсов:

```bash
curl -fsSL https://raw.githubusercontent.com/igorlion/remnanode-installer/main/install-remnanode.sh -o /tmp/install-remnanode.sh
sudo bash /tmp/install-remnanode.sh --with-zapret
```

Опция однократно скачивает базу из `kutovoys/ru_gov_zapret` и подключает её отдельным
read-only bind mount в `/usr/local/bin/zapret.dat`, как в предыдущем установщике.
Соответствие пути каталогу assets установленного Xray нужно проверить до добавления правил.
При недостающем файле Compose не создаёт каталог вместо базы.

Размер загрузки ограничен диапазоном 100000–104857600 байт. Это не проверка формата GeoSite,
содержимого базы или её совместимости с ядром. **Таймер, загрузчик обновлений и автоматические
перезапуски не создаются даже с этой опцией.** Обновление работающей базы требует отдельной
процедуры: резервная копия, проверка ядром, корректное переподключение mount, контроль памяти и откат.

Профиль Xray не изменяется автоматически. При отдельно согласованном использовании категории
`ext:zapret.dat:zapret` и `ext:zapret.dat:zapret-zapad` относятся к полю `domain`, а не `ip`.
Их направление выбирается по смыслу ресурсов; не отправляй оба списка в DIRECT автоматически.

### Существующие ноды со старым установщиком

Новая версия не отключает старый таймер и не удаляет прежние mount/файлы. Для них сначала
нужна диагностика, затем отдельное согласование миграции. Даже если профиль не использует
zapret, старый таймер может перезапускать контейнер при обновлении базы.

## Firewall

Для Ubuntu подготовлен отдельный интерактивный nftables-firewall. В обычном режиме он спрашивает только исходящий IP панели и при необходимости данные RU-моста. Порт Node API определяется из контейнера, рабочие значения повторно не запрашиваются, а после применения ставится автоматический SSH-safe rollback.

```bash
curl -fsSL https://raw.githubusercontent.com/igorlion/remnanode-installer/main/firewall/remnawave-firewall.sh -o /tmp/remnawave-firewall.sh
chmod +x /tmp/remnawave-firewall.sh
sudo /tmp/remnawave-firewall.sh apply
```

После применения не закрывай первую SSH-сессию: открой второе новое соединение и только после проверки введи `CONFIRM`. Полная инструкция: [firewall/README.md](firewall/README.md).

Для нестандартного SSH-доступа, других публичных портов, ручного IPv6 или нескольких адресных правил используй `apply --advanced`.

## Selfsteal для Reality

Отдельный скрипт устанавливает Caddy как локальную HTTPS-цель `127.0.0.1:8443`. Сертификат выпускается через публичный TCP `80`, поэтому Xray может всё время продолжать слушать TCP `443`:

```bash
curl -fsSL https://raw.githubusercontent.com/igorlion/remnanode-installer/main/selfsteal/install-selfsteal.sh -o /tmp/install-selfsteal.sh
sudo bash /tmp/install-selfsteal.sh
```

После установки укажи в Reality `target: 127.0.0.1:8443`, а домен Selfsteal используй в `serverNames` и клиентском SNI. Полная инструкция: [selfsteal/README.md](selfsteal/README.md).

## Полезные команды

```bash
# Состояние контейнера
cd /opt/remnanode && docker compose ps

# Логи контейнера
cd /opt/remnanode && docker compose logs -f -t

# Обновить ноду
cd /opt/remnanode && docker compose pull && docker compose up -d

```

## Требования

- чистый сервер Ubuntu или Debian с systemd;
- доступ `root`/`sudo`;
- созданная в панели Remnawave нода и её уникальный compose;
- исходящие HTTPS-соединения с GitHub и Docker registry.

```bash
bash -n install-remnanode.sh
bash tests/test-install-remnanode.sh
shellcheck install-remnanode.sh tests/test-install-remnanode.sh
```

Тесты используют локальные подстановки, не устанавливают пакеты и не запускают Docker.
