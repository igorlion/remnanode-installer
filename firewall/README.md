# Безопасный firewall Remnawave Node / Xray

Скрипт рассчитан на Ubuntu VPS, где Remnawave Node/Xray работают в Docker `network_mode: host`. Он создаёт только собственную таблицу `inet remnawave_guard`, не очищает чужие таблицы и никогда не выполняет `flush ruleset`.

## Обычный запуск

Запускайте скрипт **один раз**. Отдельный предварительный `--dry-run` не нужен:

```bash
chmod +x remnawave-firewall.sh
sudo ./remnawave-firewall.sh apply
```

В обычном режиме скрипт сам:

- находит `NODE_PORT` контейнера `remnanode`;
- сохраняет текущий SSH-порт;
- открывает публично только TCP `80` и `443`;
- включает эти публичные порты для IPv4 и IPv6;
- сохраняет уже добавленные ограничения для мостов;
- показывает короткий итог и ставит страховочный откат на 180 секунд.

При первой настройке нужно указать только публичный исходящий IP **сервера Remnawave Panel**. Это адрес, с которого панель подключается к Node API, а не IP настраиваемой ноды.

Если нода принимает мост от RU-ноды, ответьте «Да» на один отдельный вопрос, укажите IP RU-ноды и порт (по умолчанию `9999`). Скрипт сам разрешит TCP и UDP только с этого IP. Повторного цикла добавления в обычном режиме нет.

При повторном запуске скрипт находит сохранённую конфигурацию и предлагает применить её без повторного ввода данных.

После применения **не закрывайте первую SSH-сессию**. Откройте вторую новую SSH-сессию, проверьте Remnawave Node и подключение VLESS. Только после этого в первой сессии введите ровно `CONFIRM`. Без подтверждения правила автоматически откатятся.

## Расширенный режим

Если нужны нестандартный SSH-доступ, другие публичные порты, ручной выбор IPv6 или несколько адресных правил:

```bash
sudo ./remnawave-firewall.sh apply --advanced
```

Дополнительные диагностические опции:

```bash
# Сформировать и проверить правила, ничего не применяя
sudo ./remnawave-firewall.sh apply --dry-run

# Показать полный сгенерированный nftables-конфиг
sudo ./remnawave-firewall.sh apply --show-rules
```

## Что важно знать

Вводите обычные IP без `/32`, `/128` и других масок — скрипт добавит точную маску самостоятельно. В nftables нельзя надёжно разрешить источник «по домену»: правила фильтруют IP, а DNS-запись может измениться. Нужен именно публичный исходящий IP сервера панели. Если у панели несколько статических IP, укажите их через запятую. IP, полученный простым разрешением домена, используйте только если вы точно знаете, что панель устанавливает соединение с нодой именно с этого адреса и домен не находится за CDN/reverse proxy.

Если SSH-терминал или буфер обмена добавит к IP/порту невидимый посторонний байт, скрипт удалит его, покажет предупреждение и затем всё равно выполнит строгую проверку очищенного значения.

Если оставить для SSH значение по умолчанию `0.0.0.0`, SSH-порт будет доступен со всего интернета. В этом режиме используйте ключи и отключите парольную авторизацию. Если указать домашний динамический IP, его смена может закрыть следующий вход; после изменения адреса firewall придётся обновить.

## Управление

```bash
sudo remnawave-firewall status
sudo remnawave-firewall test
sudo remnawave-firewall rollback
```

Повторный `apply` безопасен: создаётся новая резервная копия, а таблица заменяется одной транзакцией `nft -f`. `rollback` восстанавливает предыдущую таблицу, сохранённую конфигурацию и прежнее состояние автозагрузки.

## Важные ограничения

- `ACCEPT` в этой таблице не отменяет `DROP` в другой base-chain. Скрипт ищет UFW, firewalld, включённые `nftables.service`/`netfilter-persistent` и другие `INPUT policy drop` и требует ручного решения конфликта.
- Docker host networking проходит через host `INPUT`. Опубликованные порты Docker bridge-сети обычно проходят через `FORWARD`; скрипт предупреждает и не считает их защищёнными.
- `established/related` сохраняет уже открытую SSH-сессию, поэтому проверять нужно именно **новое** подключение.
- Разрешён ICMPv4 и ICMPv6 (включая NDP), что необходимо для нормальной работы сети. Все прочие новые входящие соединения блокируются политикой `drop`.
- Внешнюю проверку портов выполняйте с другого хоста. Проверка с самой ноды не доказывает, что внешний доступ закрыт.

Локальные тесты, не меняющие firewall:

```bash
bash tests/test-remnawave-firewall.sh
```
