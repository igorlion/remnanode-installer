# Selfsteal для Remnawave / Xray Reality

Скрипт настраивает Caddy как локальную HTTPS-цель для Reality:

- Xray продолжает слушать публичный TCP `443`;
- Caddy слушает публичный TCP `80` для ACME HTTP-01 и перенаправления на HTTPS;
- Caddy слушает только `127.0.0.1:8443` для Reality `target`;
- HTTP/3 отключён, поэтому Caddy не открывает UDP `8443`;
- сертификат выпускается без временного освобождения порта `443`.

## Перед запуском

1. Создайте A-запись домена на публичный IPv4 ноды.
2. Откройте публичный TCP `80` в firewall.
3. TCP `443` можно не освобождать: его может уже слушать Xray.
4. Если у домена есть AAAA-запись, она должна указывать на IPv6 этой же ноды.

## Установка

```bash
curl -fsSL \
  https://raw.githubusercontent.com/igorlion/remnanode-installer/main/selfsteal/install-selfsteal.sh \
  -o /tmp/install-selfsteal.sh

sudo bash /tmp/install-selfsteal.sh
```

Обычный запуск спрашивает домен. Публичный IPv4 определяется автоматически и сверяется с DNS. Если внешние сервисы определения IP недоступны, скрипт сам попросит ввести IPv4 вручную.

Неинтерактивный запуск:

```bash
sudo bash /tmp/install-selfsteal.sh \
  --domain brr1.example.com \
  --expected-ip 203.0.113.10
```

После успешной установки повторно запустить настройку можно командой:

```bash
sudo remnawave-selfsteal
```

При повторной настройке сохранённый домен используется автоматически;
интерактивный запуск без аргументов открывает меню обслуживания.

## Настройка Reality

В серверном профиле Xray:

```json
{
  "realitySettings": {
    "target": "127.0.0.1:8443",
    "serverNames": [
      "brr1.example.com"
    ]
  }
}
```

Домен в `serverNames` должен совпадать с доменом, переданным скрипту. В клиентском Host/SNI используется тот же домен.

## Защита от ошибок

- проверяются DNS, A/AAAA-записи и публичный IPv4;
- чужой Caddyfile не заменяется без явного `--force`;
- занятые не-Caddy процессом порты `80` и `8443` приводят к остановке;
- конфигурация проходит `caddy validate` до установки;
- при ошибке прежние Caddyfile и страница восстанавливаются;
- резервные копии хранятся в `/var/lib/remnawave-selfsteal/backups`.

Локальная проверка кода, не меняющая сервер:

```bash
bash -n selfsteal/install-selfsteal.sh
bash selfsteal/install-selfsteal.sh self-test
bash selfsteal/tests/test-install-selfsteal.sh
```

## Управление — версия 1.1.0

На уже настроенной ноде обычный интерактивный запуск `sudo remnawave-selfsteal`
открывает меню. Для явного запуска: `sudo remnawave-selfsteal menu`.
Существующий способ установки и флаги `--domain`, `--expected-ip`, `--force`
сохранены. Для перенастройки без меню: `sudo remnawave-selfsteal install`.

| Команда после `sudo remnawave-selfsteal` | Действие |
| --- | --- |
| `status` | Состояние Caddy и сохранённый домен |
| `check` | Проверка локального HTTPS, сертификата, слушателей и HTTPS через локальный вход 443 |
| `logs` | Последние 100 строк журнала Caddy |
| `start`, `stop`, `restart` | Управление только системным Caddy с нашим Caddyfile |
| `backup` | Сохранение файлов и состояния сервиса |
| `backups` | Имена доступных полных копий |
| `restore ИМЯ` | Восстановление выбранной копии; перед ним сохраняется текущее состояние |
| `page /root/site.html` | Установка своей HTML-страницы с резервной копией и проверкой |

Своя страница при установке:

```bash
sudo bash /tmp/install-selfsteal.sh install \
  --domain brr1.example.com --expected-ip 203.0.113.10 \
  --page /root/site.html
```

Повторная установка сохраняет текущую страницу, если `--page` не указан.
Страница должна быть самодостаточной: команда копирует один HTML-файл,
а не каталог изображений, CSS и JavaScript. Файл становится публичным сайтом.

`check` проверяет доверие к сертификату и совпадение HTTP-ответа с установленной
страницей. Проверка входа 443 выполняется с самой ноды через loopback. Она
не доказывает доступность из РФ и работу авторизованного VPN-туннеля:
последние проверяются отдельным клиентским подключением. Ошибка входа 443
не откатывает успешную установку Caddy: сначала нужно задать target и SNI
в профиле Remnawave. Скрипт не меняет профиль, ключи REALITY или роутинг.

Сертификаты продлевает сам Caddy; отдельный cron и принудительный перевыпуск
не нужны. При неудачном выпуске нет подмены самоподписанным сертификатом.

### Резервные копии и ограничения отката

Полная копия версии 1.1.0 включает Caddyfile, HTML-страницу, сохранённый домен,
установленный CLI и прежнее состояние Caddy (запущен/остановлен, автозапуск).
Сохраняется также отсутствие файлов: при ошибке первой установки новые файлы
удаляются, а сервис возвращается в прежнее состояние. Ошибки и INT/TERM
запускают автоматический откат; SIGKILL или потеря питания его не запускают.

Копии создаются до установки пакетов, в каталоге с правами 0700. Установленные
или обновлённые APT-пакеты и хранилище сертификатов Caddy при откате не удаляются.
Старые частичные копии v1.0.x остаются на диске, но не предлагаются командой
`restore`: в них нет необходимых сведений о состоянии сервиса.
Если восстановлена копия старого CLI, для повторного доступа к новым командам
используйте скачанный установщик v1.1.0. После восстановления другого домена
вручную согласуйте SNI с профилем и клиентом.

Параллельные изменения блокируются через `flock`. Конфликтующие процессы,
включая Caddy в Docker, не останавливаются. Проверяется каждый слушатель
портов 80/8443; HTTPS на 8443 должен быть привязан исключительно к loopback,
UDP/8443 запрещён. Все A-записи домена должны указывать на выбранную ноду.

Дополнительные тесты без изменения системы:

```bash
python3 selfsteal/tests/test-management.py
```
